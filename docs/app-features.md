> 앱 기능 노트. 맨 앞의 "감정 펫"·`emotion/` 설명과 "온디바이스 모델 (v16)" 절은 지금 코드에서 빠진 이전 버전 내용이다. 알림 브리핑, 약속, 할 일, 지출 장부 부분이 현재 기능이다.

# 마음펫 (MaeumPet)

카톡이나 문자를 보내기 전에, 작은 텍스트 얼굴 펫이 지금 내 감정을 비춰 주는 안드로이드 앱.
"보내고 나서 후회"를 줄이는 게 목표다. 글은 폰 밖으로 절대 나가지 않는다.

## 어떻게 동작하나

1. 접근성 서비스가 지정한 앱(카카오톡, 문자 등)의 입력창 글자만 읽는다. 비밀번호 입력은 읽지 않는다.
2. 규칙 기반 한국어 감정 분석기가 폰 안에서 온도(0~100)를 계산한다.
3. 화면 구석의 펫이 표정으로 반응한다.
   - `:)` 평온  `:D` 기쁨  `:(` 슬픔  `:/` 날카로움  `D:` 뜨거움  `^^` 잘 참았을 때
4. 뜨거워지면 펫이 카드를 열고 10초를 같이 센다. 끝나면 덜 날카로운 문장 세 가지를 제안한다.
   "이걸로 바꾸기"를 누르면 입력창의 글이 그 문장으로 바뀐다.
5. 펫은 나를 배운다.
   - "괜찮아, 장난이야": 그 표현들은 앞으로 덜 예민하게 본다.
   - 기록에서 "후회했어": 그 표현들은 앞으로 더 일찍 알려 준다.
   - 평소 말투 온도를 기억해서, 원래 말이 센 사람에게는 기준을 조금 올린다.
   - 시간대, 앱별 경향을 "내가 알게 된 너"에 문장으로 보여 준다.

## 빌드와 설치

- Android Studio에서 이 폴더를 열거나, 터미널에서:

```
gradlew.bat clean assembleDebug --no-build-cache
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

- 휴대폰에 전달할 APK는 위처럼 전체 빌드한다. 화면 리소스와 생성된 ViewBinding의 식별자가 어긋난 산출물에서는 `Missing required view` 오류로 첫 화면이나 접근성 서비스가 종료될 수 있다.
- 설치 후 `am start`의 성공만으로 실행 확인을 끝내지 않는다. 메인 화면의 활성 상태, 프로세스 유지, 해당 프로세스의 새 충돌 로그가 없는지 확인한다. `install -r`은 기존 앱 데이터를 유지한다.

- 폰에서 앱을 열고 "접근성 설정에서 마음펫 켜기"를 누른다.
- 설정 > 접근성 > 설치된 앱(또는 다운로드한 앱) > 마음펫 > 사용 켜기.
- 카카오톡을 열면 펫이 나타난다. 드래그해서 자리를 옮길 수 있고, 탭하면 카드가 열린다.

## 온디바이스 모델 (v16)

`app/src/main/assets/model/` 에 KoELECTRA-small 기반 분류기가 들어 있다 (INT8 ONNX 15MB, 폰에서 문장당 수십 ms).

- 출력: 감정 7종(분노 슬픔 불안 상처 당황 기쁨 중립) + 공격성 3단계(없음 거친말 혐오)
- 사전(`Lexicon.kt`)과 합쳐서 쓴다. 모델은 "상대에게 거칠게 들릴 확률"을 온도에 더하고, 사전은 이유 설명과 개인화 학습을 맡는다.
- 학습 코드와 실험 기록: `D:\Koelectratilet\v16\` (`EXPERIMENTS.md`). 모델 교체는 `export_onnx.py` 결과의 `model.quant.onnx`, `vocab.txt`, `labels.json` 세 파일을 assets 에 복사하면 된다.
- 모델 파일이 없으면 자동으로 사전만으로 동작한다.

## 알림 브리핑 (펫이 자는 동안 하는 일)

설정 > 알림 접근에서 마음펫을 켜면 폰에 뜨는 알림을 폰 안에만 저장한다.

- 인증번호·OTP, 진행 중 알림(음악·다운로드), 광고는 걸러내거나 낮게 본다.
- 카톡·문자·메일은 보낸 사람과 내용, 결제 알림은 금액을 뽑는다. 알림을 "눌러서 열었는지 / 밀어서 지웠는지"도 기록해 보낸 사람별 중요도를 배운다.
- 화면을 15분 이상 끈 뒤 잠금을 풀면, 그동안 수집한 대화와 메일을 묶어 브리핑 알림으로 보여 준다. 앱 첫 화면의 "지금 브리핑"으로 수동 확인할 수도 있다.
- 밤에 충전 중일 때 `NightWorker`가 보낸 사람 통계를 다시 계산하고, 보관 기간(기본 7일)이 지난 원문을 지우고, AI 요약 기능을 준비한다. 브리핑은 사용자가 돌아올 때 만든다.
- "알림 요약 · 지출 장부"에서 핵심 요약과 저장된 원문을 전환해 확인할 수 있다.

삼성 폰은 배터리 설정에서 마음펫을 "제한 없음"으로 두어야 밤새 알림을 놓치지 않는다.

### 펫이 밤에 배우는 것
- **중요도 분류기** (`ImportanceLearner`): 알림을 눌러 열었으면 1, 밀어 지웠으면 0. 종류·질문 여부·금액·보낸 사람 통계·시각·온디바이스 모델의 감정 확률을 특징으로 하는 로지스틱 회귀를 폰 안에서 학습한다(라벨 100개 이상일 때). 규칙 점수와 반반 섞어 쓴다.
- **Gemini Nano 요약** (`NanoSummarizer`): 지원 기기면 충전 중에 요약 기능을 내려받고, 같은 사람과 3개 이상 주고받은 메시지를 한 줄로 줄여 브리핑에 넣는다. 미지원이면 핵심 문장을 추리는 오프라인 요약을 사용한다. 첫 화면의 Nano 상태 문구를 누르면 바로 확인할 수 있다.

## 약속 기억하기

`PlanExtractor` 가 받은 메시지와 내가 보낸 말에서 "내일 7시에 볼까?", "다음주 수요일 점심 어때?", "내일 말고 모레 보자", "미안 못 갈 것 같아" 같은 문장을 찾아 약속 후보로 만든다. 날짜·시간 표현은 규칙으로 해석한다(오늘/내일/모레, 요일, 9월 12일, 오후 3시 반, 저녁 등).

- 펫은 추측만 하고 첫 화면의 "약속" 카드에서 사용자가 "맞아" / "아니야"로 정한다.
- 확정되면 당일 아침 8시 30분과 한 시간 전에 알려 준다. 브리핑에도 "오늘 약속"이 붙는다.
- 단위 테스트: `app/src/test/.../PlanExtractorTest.kt`

## 오늘 한눈에 보기와 알림에서 할 일 만들기

- 첫 화면의 **오늘 한눈에 보기**는 기기 현지 날짜 기준으로 확정된 약속, 확인할 주요 알림, 오늘 순지출, 오늘 마감·기한 지난 할 일을 표시한다. 화면을 다시 열거나 날짜가 바뀌면 갱신한다. 약속 전체 보기, 알림, 지출 장부, 할 일로 바로 이동할 수 있다.
- 주요 알림은 오늘 수신한 알림의 최신 갱신본을 기준으로 기존 중요도 규칙을 적용한다. 눌러 열거나 지운 알림은 제외하지만 다른 앱에서 직접 읽었는지는 알 수 없다. 지출은 오늘 수신한 결제에서 오늘 수신한 환불을 뺀 값이다.
- **할 일 → 추천**에서 제출·회신·확인·구매·준비 같은 요청을 검토하고 **할 일로 저장**을 누른다. 저장 전에 내용을 편집하고 마감일을 선택하거나 지울 수 있다. 원문 알림에서도 인식한 요청이 있으면 **할 일 추천 보기**로 이동한다.
- 마감일은 알림의 원래 수신일을 기준으로 오늘·내일·모레, `YYYY-MM-DD`, `M월 D일`을 해석한다. 여러 날짜가 모호하게 나오거나 지원하지 않는 표현이면 날짜를 확정하지 않는다. 시간 단위 마감 및 할 일의 자동 알람은 제공하지 않는다.
- 사용자가 저장한 것만 할 일에 포함된다. 완료·되돌리기·수정·삭제를 지원한다. 추천 제외/삭제 후 같은 원본을 다시 가져와도 되살리지 않는다. 이후 취소 알림이 와도 저장한 할 일을 자동 취소하지 않으므로 사용자가 확인한다.
- 기존에 보관 중인 알림도 첫 화면/할 일 화면 진입 및 야간 정리 시 처리한다. 할 일과 추천의 내용·출처·원문은 알림 보관 기간과 독립적으로 기기에 저장되며, 항목 삭제 시 내용과 원문을 지우고 중복 방지 식별값을 유지한다.
- 알림 DB v3→v4는 기존 테이블을 유지하고 `todos`만 추가한다. 회귀 테스트 `TodoOverviewTest`는 요청/일상 대화 구분, 날짜 추정, 누적 알림 중복, 여러 요청, 오늘 알림·지출·할 일 집계를 검증한다.

## 부재중 소식 브리핑 (2026-09-15)

- **화면을 끈 동안:** 알림 수집 서비스가 화면 꺼짐을 관찰한 시점부터 15분 이상 지나 잠금을 풀면 브리핑한다. 잠을 잤다고 단정하지 않는다. 서비스가 꺼져 있던 동안의 알림은 복구하지 못한다.
- **게임·집중 중:** 첫 화면에서 `게임·집중 시작`을 누르면 자동 브리핑을 멈추고 소식을 모은다. 게임 후 마음펫을 열어 `돌아왔어 · 모은 소식 보기`를 누른다. 게임 종류와 종료를 자동 감지하지 않는다.
- 같은 알림의 갱신 기록을 합쳐 메시지 순서를 유지한다. 동일 이름의 별도 대화방과 메일 스레드는 알림 키로 구분한다. 표시 이름만으로 합치지 않는다.
- 메일은 질문·시간 표현이 없어도 포함한다. 질문·요청·시간 표현이 있는 대화를 먼저 보여 준다. 단체방을 근거 없이 ‘잡담’으로 분류하지 않는다.
- Gemini Nano가 가능하면 AI 요약과 마지막 원문을 함께 표시하고, 불가능하면 핵심 문장 최대 2개를 원래 순서대로 추려 표시한다. 요약은 사실 검증을 보장하지 않는다.
- Android 알림과 앱 안의 브리핑 카드로 전달한다. 홈 화면 펫 팝업은 아래의 접근성 설정을 통해 사용할 수 있다. 소식별 원래 대화방 열기는 아직 구현하지 않았다. `받은 알림`에서 저장된 내용을 확인할 수 있다.
- 알림 접근 외에 접근성 권한은 이 브리핑에 필요하지 않다. 자동 브리핑에는 앱 알림 및 ‘펫의 브리핑’ 채널이 켜져 있어야 한다. 전달 실패 시 확인 시각을 갱신하지 않아 수동으로 다시 확인할 수 있다.
- 알림을 눌러 연 기록은 제외하지만, 앱 안에서 직접 읽거나 답장했는지는 알 수 없다. 알림에 없는 과거 대화·메일 본문을 읽지 않는다.

### 기기 확인 순서

1. 알림 접근 및 앱 알림을 켠다.
2. 화면을 끄고 15분 이상 기다리는 동안 다른 기기에서 카톡·메일을 보낸 뒤 잠금을 푼다.
3. 브리핑 알림을 누르면 같은 내용이 앱 카드에 표시되는지 확인한다. 다시 잠금을 풀었을 때 같은 소식이 반복되지 않는지 확인한다.
4. 게임·집중 시작 → 카톡 수신 → 돌아왔어를 눌러 집중 시간의 소식을 확인한다.
5. `7시 → 8시 변경`, 같은 대화의 누적 알림, 메일만 수신, 새 소식 없음, 알림 채널 차단도 확인한다.

자동 테스트: `AwayDigestTest`는 부재 시간, 브리핑 시간 경계, 누적 메시지 중복, 변경 순서, 메일 포함, 방 구분, 알림 클릭 후 새 메시지, 타임스탬프 누락을 검증한다.


## 홈 화면 펫 팝업

- 앱 첫 화면의 `홈 화면에서 펫 팝업 보기`를 켜고, Android 접근성 설정에서 마음펫을 활성화한다. 기존 접근성 오버레이를 사용하며 SYSTEM_ALERT_WINDOW 권한은 추가하지 않는다.
- 자동 브리핑 알림이 생성된 뒤 기본 홈 앱이 보이고 화면 잠금이 풀려 있을 때, 하단에 펫과 스크롤 가능한 소식 카드를 한 번 표시한다. 다른 앱 사용 중이면 홈으로 돌아올 때까지 기다린다.
- `자세히 보기`는 마음펫을 열고, `닫기`는 팝업을 없앤다. 새 브리핑마다 한 번만 표시하며, 앱에서 확인한 브리핑이나 24시간 이상 지난 브리핑은 다시 띄우지 않는다.
- 화면 꺼짐·잠금·다른 앱 전환·집중 모드·팝업 끄기 시 숨긴다. 폴드 접기/펼치기나 화면 회전 시에도 팝업을 닫으며 본문은 앱에서 계속 확인할 수 있다.
- 자동 브리핑의 기존 조건(15분 이상 화면 꺼짐, 알림 접근, 앱 알림 채널 허용)이 적용된다. 수동 브리핑을 다시 팝업으로 표시하지 않는다.
- 기기 검증: 새 자동 브리핑 수신 후 홈 진입, 카톡·게임에서는 미표시, 닫은 뒤 재진입 시 미표시, 화면 잠금 시 숨김, 접힌 화면/펼친 화면 및 큰 글꼴에서 스크롤과 버튼 확인.
- JVM 테스트는 표시 조건만 검증한다. 접근성 창 표시와 One UI 홈 전환은 실기기 검증이 별도로 필요하다.

## 알림 요약과 지출 장부 (2026-09-17)

- 첫 화면 → **알림 요약 · 지출 장부**: 최근 알림 300개를 알림 키별로 묶는다. **핵심 요약 / 원문** 전환 및 항목 터치로 저장된 원문 확인이 가능하다.
- 핵심 요약은 기기 지원 여부와 관계없이 동작하는 추출식 요약이다. 질문·일정·요청 같은 핵심 문장과 마지막 문장을 최대 2개 남기며, 긴 문장은 말줄임표로 표시한다. 생성형 재작성은 기존 Nano 지원 기기의 자동 브리핑에서만 사용한다.
- **지출 장부**: 원화 결제·승인과 취소·환불 알림의 금액·사용처·수신 시각·앱 이름을 별도 저장한다. 입금·이체·충전·결제 예정·실패·광고 및 금액이 모호한 알림은 자동 저장하지 않는다. 모든 금융사 형식을 지원하는 것은 아니다.
- 월별 결제액, 환불액, 순지출 및 사용처별 순지출을 보여 준다. 환불은 환불 알림 수신 월에 차감하며 원결제를 소급 삭제하지 않는다. 사용처를 찾지 못하면 `사용처 미확인`으로 표시한다. 항목을 눌러 사용처·금액 수정 또는 삭제가 가능하다.
- 동일 원본은 중복 저장하지 않는다. 거래 일시가 포함된 동일 알림 키·내용의 재게시도 합친다. 다른 앱에서 온 결제 알림이나 거래 일시가 없는 새로운 알림은 중복일 수 있으므로 장부에서 확인·삭제한다.
- 기존 DB v2 기록을 지우지 않고 v3에 지출 테이블만 추가한다. 남아 있는 과거 알림은 장부 진입 및 야간 정리 시 가져온다. 이미 삭제된 알림은 복구할 수 없다.
- 지출은 알림 원문 보관 기간과 독립적으로 기기에 남는다. 삭제 시 사용처·금액·앱 이름은 지우고 재수집 방지용 식별값을 유지한다. 외부 서버로 보내지 않는다. 자동 수집에는 기존 알림 접근 및 알림 브리핑 설정이 필요하다.
- 단위 테스트: `ExpenseExtractorTest`, `NotificationSummaryTest`. 실기기에서는 금융사별 알림 형식, 월 이동, 수정·삭제, 앱 재시작 후 보존, 기존 버전 업데이트를 별도로 확인한다.
