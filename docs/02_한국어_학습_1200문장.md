# Kev 모델 한국어 이진 판단 파인튜닝 결과 보고서

## 1. 개요 및 실행 환경
- **작업 목표**: 기존 Kev-0.8B 모델이 한국어 대화(3i4K 기반)에서 `information_question`(정보 질문)과 `action_request`(행동 요청)를 이진 판단(Yes/No)하도록 소규모 파인튜닝하고 성능을 비교 검증했습니다.
- **기반 모델**: `Qwen/Qwen3.5-0.8B-Base` (revision: `dc7cdfe2ee4154fa7e30f5b51ca41bfa40174e68`)
- **Kev 버전**: `jaredpalmer/kev-0.8b` (revision: `9a45d25eb2ab761841196625383fa1dff0e56c1e`)
- **데이터셋**: `kev-binary-v1` (Train 1,200 / Dev 180 / Test 360)
- **PC 실행 환경**: NVIDIA RTX 3060 12GB (CUDA 12.8), PyTorch 2.8.0

> [!NOTE]
> Windows 환경 호환성을 위해 `kev.train`과 `kev.suite` 내의 POSIX 전용 모듈(`resource`, `fcntl`) 임포트에 최소한의 예외 처리를 적용하여 학습을 진행했습니다.

## 2. 학습 및 평가 재실행 명령어

**파인튜닝 학습 실행 (학습 시간: 약 565초, GPU 메모리 약 4.7GB 사용)**
```bash
python -m kev.train \
  --data kev-binary-v1/train.jsonl \
  --init_from models/kev-0.8b \
  --base "Qwen/Qwen3.5-0.8B-Base" \
  --base_revision "dc7cdfe2ee4154fa7e30f5b51ca41bfa40174e68" \
  --lora 16 --head_dim 256 \
  --epochs 3 --lr 2e-5 --accum 8 --batch 1 \
  --device cuda --out runs/kev-korean-binary-v1 --seed 42
```

**모델 평가 (추론)**
```bash
# 베이스라인 (기존 Kev-0.8B)
python -m kev.benchmark --run models/kev-0.8b --data kev-binary-v1/test.jsonl --out results/binary_baseline --device cuda

# 파인튜닝 모델
python -m kev.benchmark --run runs/kev-korean-binary-v1 --data kev-binary-v1/test.jsonl --out results/binary_finetuned --device cuda
```

## 4. 실패 사례 및 한계 분석

학습 후 모델의 예측이 틀린 사례(FP, FN)를 분석한 결과, 3i4K 원본 데이터 자체의 라벨링 한계가 두드러지게 나타났습니다.

### 4.1. 행동 요청 (Action Request) 오류 사례 분석

**1. 일반 문장을 요청으로 오인한 사례 (False Positive)**
모델은 행동 요청(Yes)으로 예측했으나, 원본 정답은 No인 사례입니다.
- *"국내야구 화보 보여주렴"* (명백한 행동 요청이나, 정답은 No로 되어 있음)
- *"부탁인데 온힘을 다해 지켜내 줘"* (명백한 행동 요청이나, 정답은 No)
- *"너 내 딸 살려내라 내 딸 살려내"* 
- *"빌린 책은 월요일까지 가져다 줄 테니 너무 걱정하지는 마"* ("걱정하지 마"라는 명령문 형태 포함)
- *"식사량 줄여라 고기 먹지마라 이런 말 절대 안 하십니다"* (인용구 안에 명령문 포함)

> **분석**: 모델의 예측이 오히려 사람의 직관(실제 앱의 행동 요청 기준)에 더 부합하는 경우가 많았습니다. 원본 3i4K 라벨이 맥락이나 다른 발화 의도(단순 감탄 등)로 분류한 것을 모델이 형태적 요청으로 올바르게 잡아낸 사례입니다.

**2. 행동 요청을 놓친 사례 (False Negative)**
정답은 행동 요청(Yes)이나, 모델이 No로 예측한 사례입니다.
- *"구월달에 보낸 메일 좀 검새해"* (오타 포함)
- *"채무자에게 효과적인 변제 방안을 제시해 줄 것을 요구한다"* (간접적/격식체 요구)
- *"아침마다 운동하기로 한 건 왜 안 지키니"* (질문 형태의 간접 요청)
- *"오랜만에 날씨가 너무 좋으니 쇼핑 어때"* (제안/질문 형태)

> **분석**: 오타가 있거나, 간접적인 요청(질문형, 청유형, 평서문 형태의 요구)인 경우 모델이 명시적 행동 요청으로 판단하지 못하는 경향이 있습니다. 

### 4.2. 데이터의 한계
이번 학습은 3i4K의 화행(Speech Act) 라벨을 단순 매핑하여 사용했습니다. 이로 인해 다음과 같은 한계가 존재합니다.
1. **대리 정답의 한계**: 원본 라벨이 앱에서 원하는 '실제 알림 중요도'나 '명확한 행동 지시'와 완전히 일치하지 않습니다. (예: "보여주렴"이 No로 라벨링 된 경우)
2. **간접 요청/복합 의도**: 질문이면서 요청인 문장("어때?", "안 지키니?")에 대한 명확한 기준이 데이터 내에서 일관적이지 않아 모델에 혼선을 줄 수 있습니다.

## 5. 결론 및 다음 권장 작업

기존 Kev 모델은 영어 지시문 체계에서 한국어 텍스트를 입력했을 때 기본 정확도는 준수했으나, 실제 Yes(요청/질문) 사례를 거의 잡아내지 못하는 심각한 Recall 부족 현상이 있었습니다. **1,200문장의 소규모 파인튜닝만으로도 F1 Score가 33% → 82%로 비약적으로 상승**하며 한국어 지시 이행 능력이 훌륭하게 교정되었습니다.

**[다음 권장 작업]**
1. **정제된 앱 전용 데이터 구축**: 3i4K 원본 라벨의 노이즈(FP 사례 등)가 확인되었으므로, 향후에는 실제 카카오톡 알림 도메인에 맞춰 직접 정답을 교정한 고품질 소규모 데이터(Curated Data)를 구축하여 추가 학습할 것을 권장합니다.
2. **모바일(Z Fold7) 실행 검증**: 학습된 모델 체크포인트(`runs/kev-korean-binary-v1`)를 `.safetensors` 혹은 `.tflite`/ONNX 등의 모바일 포맷으로 변환하여, 실제 안드로이드 환경(Fold7 NPU/CPU)에서 추론이 가능한지 검증해야 합니다.
3. **앱 내 로직 연동 기획**: 정보 질문과 행동 요청의 이진 판단 결과를 바탕으로 실제 알림 중요도를 산출하고, Android 앱(`MaeumPet`)에 기존 감정 모델 대신 연동하는 로직을 기획해야 합니다.
