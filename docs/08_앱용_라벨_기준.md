# 한국어 알림 분류: 학습과 검토 기준

## 이번에 학습하는 첫 모델

합의한 방식은 **Kev-0.8B + 영어 내부 지시문 + 한국어 원문 + 분리된 이진 판단**입니다. 한국어 메시지는 번역하지 않습니다. KoELECTRA로 변경하려던 준비는 중단했으며, `mobile-request-v1`은 현재 학습 경로에서 사용하지 않습니다.

| 판단 | 원본 3i4K 정답 매핑 | 의미와 한계 |
|---|---|---|
| information_question | 질문(2)이면 yes, 나머지 no | 답을 구하는 질문. 단순 안부와 긴급 승인 요청은 구별하지 못함 |
| action_request | 명령(3)이면 yes, 나머지 no | 원 데이터 기준의 요청/지시. 질문 형태의 간접 요청과 다를 수 있음 |

억양 의존(6)은 이번 이진 학습에서 제외합니다. `kev-binary-v1`에 학습 1,200개, 검증 180개, 평가 360개를 분리했습니다. 두 판단은 별도 질문으로 표현하며 한 요청에 함께 담을 수 있습니다. 학습 시 선택지 순서를 섞습니다. 평가 시 정확도뿐 아니라 양성 재현율과 오탐률을 함께 봅니다. 학습 전 Kev와 학습 후 Kev에 동일한 평가 입력을 사용합니다.

학습하지 않는 것: 긴급도, 일정 변경, 마감 시각, 스팸 여부, 상대방의 중요성. 첫 모델만으로 중요/나중에/보관함을 결정하거나 알림을 삭제하지 않습니다.

## 실제 앱용 추가 정답 검토

기존 대화 400개에 아래 항목을 별도로 검토해야 합니다. 기존 요약은 미래 발화를 포함할 수 있으므로 정답 판단이나 입력에 쓰지 않습니다. 알림 시점과 직전 대화만 봅니다.

- reply_requested: 나에게 답변이나 확인을 요구하는가? 예/아니오/불명.
- action_requested: 정보 대답 이외의 행동을 요구하는가? 질문형 부탁도 포함. 예/아니오/불명.
- schedule_change: 기존 일정·장소의 변경이나 취소가 명시되었는가? 예/아니오/불명.
- deadline_explicit: 완료 기한이 명시되었는가? 예/아니오/불명. 기한 원문을 함께 기록.
- urgency: 즉시 확인/나중에 가능/불명. 근거와 수신 시각을 함께 기록. 날짜 표현만으로 자동 확정하지 않음.
- archive_candidate: 내용 없는 반복 반응·광고 등 보관 대상인가? 불명확하면 아니오 또는 불명.

예시(설명용이며 평가 정답이 아님):

- “오늘 3시까지 보고서 보내줘”: 행동 요청, 명시적 마감. 긴급도는 수신 시각과 맥락에 따라 달라짐.
- “회의 3시에서 4시로 바뀌었어”: 일정 변경. 명령문이 아니어도 중요할 수 있음.
- “자료 보내주실 수 있나요?”: 앱 기준 행동 요청. 문장 유형 모델은 질문으로 분류할 수 있음.
- “밥 먹었어?”: 질문. 질문이라는 이유만으로 긴급 탭으로 보내지 않음.

실제 앱용 라벨은 검토자가 원문 근거를 확인한 뒤 확정합니다. 자동 생성한 제안은 draft로만 기록하고 최종 평가 정답으로 사용하지 않습니다.

## 기기 실행

목표 기기는 사용자가 알려준 Galaxy Z Fold7입니다. 기존 앱의 ONNX 경로가 Kev를 바로 실행할 수 있다는 뜻은 아닙니다. Kev의 기반 모델, 토크나이저, 결정 헤드를 지원하는 Android 실행 경로를 따로 검증해야 합니다. PC 한국어 정확도 평가와 폰의 속도·메모리·배터리 평가는 별개입니다. 현재 폰 실측 결과는 없습니다.
