# Kev 재학습 데이터 생성 프롬프트 (안티그래비티용)

- 프롬프트 1: 알림 분류 데이터 (광고·잡알림 / 지금 알아야 하는가) ← 먼저
- 프롬프트 2: 카톡 질문·요청 데이터 (카톡 말투 보강)

결과 파일은 `E:\AI 키보드 앱 만들기~\dataset-evaluation\kev-notif-v1\raw\` 에 저장한다.
한 번에 100줄씩, 배치마다 파일 하나(`notif_01.jsonl`, `notif_02.jsonl` …, `chat_01.jsonl` …).
목표 분량: 알림 3,000줄(30배치), 카톡 2,000줄(20배치). 배치마다 아래 프롬프트를 그대로 쓰고 맨 끝의 배치 번호만 바꾼다.

---

## 프롬프트 1: 알림 분류

```
너는 한국 스마트폰 알림 분류 모델의 학습 데이터를 만드는 데이터 엔지니어야.
한국 안드로이드 폰에 실제로 뜨는 것과 구분이 안 될 만큼 사실적인 "합성 알림"을 만들고, 각 알림에 두 가지 라벨을 붙여.

## 출력 형식
- JSON Lines. 한 줄에 알림 하나, 다른 설명 문장은 절대 쓰지 마.
- 필드:
  {"app": 앱 이름, "title": 알림 제목(없으면 ""), "text": 알림 본문,
   "promo": "yes"|"no", "timely": "yes"|"no",
   "category": 아래 분류 중 하나, "hard": true|false, "why": 라벨 이유 한 줄(한국어)}
- category: ad, engagement, reward, transaction, delivery, security, bill, schedule, reservation, public, mail_person, mail_service, newsletter, content, device, system

## 라벨 1: promo (앱을 열게 하려는 알림인가)
"yes" = 사용자가 한 일의 결과가 아니라, 보낸 회사가 자기 이익을 위해 사용자를 앱으로 끌어들이려는 알림.
  - 광고, 할인, 특가, 쿠폰 지급, 이벤트·응모·복권, 포인트·리워드 받으러 오라는 것
  - "오늘 출석체크 안 했어요", "연속 기록이 끊겨요", "장바구니 상품 가격이 내려갔어요", "회원님을 위한 추천"
  - "(광고)" 표시가 없어도 성격이 위와 같으면 yes
"no" = 사용자의 행동·계정·거래·약속의 결과이거나, 사람이 보낸 것, 기기 상태 등.
  - 결제 승인·취소, 입출금, 택배 상태, 로그인·보안 경고, 요금 청구·미납, 예약 확정·변경, 재난문자, 사람이 보낸 메일, 구독한 작품의 새 회차

## 라벨 2: timely (오늘 안에 알아야 하거나 해야 할 일이 있는가)
"yes" = 지금 또는 오늘 안에 보지 않으면 손해·위험·불편이 생기는 것.
  - 보안 경고(새 기기 로그인, 비밀번호 변경), 결제·출금 승인(본인이 한 게 맞는지 확인 필요), 결제 실패
  - 오늘·내일 도착/도착 완료 택배, 오늘·내일 일정·예약, 일정·기한 변경이나 취소, 납부 기한 임박, 재난·안전 문자
  - 사람이 보낸 메일 중 답장·제출·확인을 요구하는 것
"no" = 나중에 한꺼번에 봐도 되는 것.
  - 뉴스레터, 주간 리포트, 팁, 콘텐츠 추천, 단순 참고 소식("팀원이 합류했습니다"), 기기 상태(이어폰 배터리 90%), 재생 중 음악
  - promo가 yes인 알림은 "오늘 자정 종료!", "지금 안 받으면 사라져요"라고 해도 항상 no (가짜 긴급함)

## 헷갈리기 쉬운 경우의 정답 (반드시 이대로)
- 리뷰·후기·상품평을 쓰면 포인트를 준다는 알림, 랭킹·등급 승급 유도 → promo yes
- 구독한 채널·작품의 새 소식(웹툰 새 회차, 구독 스트리머 방송 시작, 구독 유튜버 새 영상) → promo no, timely no
- 플랫폼이 골라 준 추천("회원님을 위한 추천", 구독하지 않은 신작 공개) → promo yes
- 사용자가 방금 앱에서 직접 한 일의 확인(송금 완료, 응모 완료, 결제 취소 완료, 분실 신고 접수) → promo no, timely no
- 카드 결제 승인·출금 → timely yes (본인 결제가 맞는지 확인해야 하므로)
- 기한이 3일 이상 남은 안내(5월 종소세 신고, 여권 만료 6개월 전, 연말까지 건강검진, 21일 자동이체 예정) → timely no
- 지금 몸을 움직여야 하는 기기 알림(세탁 완료, 택시 3분 뒤 도착) → timely yes / 소모품 교체 준비, 배터리 15% → timely no
- 리뷰·별점·후기 요청, 랭킹 마감, 레벨업 축하, 친구 성취 알림, 학습 복귀 유도 → 포인트가 없어도 promo yes
- 찜한 상품 가격 인하, 장바구니 리마인드 → promo yes / 사용자가 직접 신청한 재입고 알림 → promo no
- 플랫폼이 준 쿠폰의 소멸 → promo yes, timely no / 내가 모은 포인트·마일리지가 오늘·내일 소멸 → promo no, timely yes / 그보다 먼 소멸 → no, no
- 사용자가 신청한 일의 처리 완료(요금제 변경, 반품 수거, 승차권 반환, 현금서비스 입금, 서류 발급 완료) → no, no
- 배달 음식·택배가 문 앞에 도착, 오늘·내일 도착 예정, 곧 내려야 하는 역 도착, 내일 출발 항공편 체크인 → timely yes
- 예정된 자동이체·정기결제 안내(할 일 없음) → timely no / 내일 결제일인데 잔액 확인 필요 → timely yes
- 축하·기록 알림: 행동을 권하는 문구가 있으면("목표를 높여 보세요", "쿠폰을 확인하세요") promo yes / 단순 기록이면("레벨이 올랐습니다", "매너온도 40도") promo no
- 카드 결제 승인은 금액이 작아도(교통 1,400원, 커피 4,500원) timely yes / 가족 카드 사용 알림, 결제 취소 완료 → timely no
- 배송 지연 안내처럼 사용자가 할 일이 없는 소식 → timely no / 오늘 받을 물건의 시간이 바뀐 경우 → timely yes
- 새 기기 로그인 알림은 "본인이 맞다면 무시하세요"라고 해도 timely yes / 정기결제(구독료) 자동 승인 → timely no
- 팔로우·관심 등록한 아티스트·브랜드·채널의 새 소식 → 구독과 같음(promo no, timely no)
- 인증번호·본인확인 번호가 들어간 알림, "OTP", "인증 번호"라는 단어가 들어간 알림은 만들지 마

## 분포 (100줄 기준)
- promo yes 약 30줄 / no 약 70줄
- timely yes 약 35줄 / no 약 65줄
- hard: true 최소 30줄. 겉모습과 정답이 반대인 함정 사례:
  - "(광고)" 없이 자연스러운 말투의 광고: "정*현님, 이번 주 놓친 혜택이 있어요"
  - 광고처럼 보이지만 거래 결과: "쿠폰이 사용되었습니다 -3,000원", "포인트 1,250원 적립 완료" → promo no
  - 긴급해 보이는 광고: "⚠️ 오늘만! 쿠폰이 곧 사라집니다" → promo yes, timely no
  - 차분해 보이지만 중요한 것: "새로운 기기에서 로그인되었습니다", "자동이체 출금 실패" → timely yes
  - 이벤트 당첨 후 할 일: "당첨을 축하드려요! 내일까지 배송지를 입력해 주세요" → promo no, timely yes
  - 같은 앱의 광고와 거래 알림을 둘 다 만들 것 (예: 토스 광고 / 토스 송금 완료)

## 다양성
- 한 배치에 앱 20개 이상, 같은 문장 틀 반복 금지, 길이 다양하게(10자~150자).
- 앱 예시(이 밖에도 자유롭게):
  쇼핑 쿠팡, 무신사, 11번가, G마켓, 올리브영, 오늘의집, 당근 / 배달 배달의민족, 쿠팡이츠, 요기요
  금융 토스, 카카오뱅크, KB국민카드, 신한카드, 현대카드, 네이버페이, 카카오페이, 삼성페이
  택배 CJ대한통운, 우체국택배, 한진택배, 쿠팡 로켓배송 / 통신 SKT, KT, LG U+
  공공 재난문자, 국민건강보험, 홈택스, 정부24 / 교통·여행 코레일, SRT, 카카오T, 대한항공, 야놀자, 클룩
  콘텐츠 YouTube, 넷플릭스, 네이버 웹툰, 멜론, 치지직 / 학습 듀오링고, 대학 LMS(e-class)
  메일 Gmail, 네이버 메일 (사람: 교수님, 조교, 팀장, 동아리 / 서비스: GitHub, Notion, 은행 안내 / 뉴스레터)
  게임 포켓몬 GO, 메이플스토리 / 기기 Galaxy Wearable, 삼성헬스, SmartThings, LG ThinQ / 보안 Google, 네이버, 카카오 계정
- 현실 형식 흉내: 이모지, [대괄호 머리말], 마스킹된 이름(정*현), 금액(32,000원), 날짜·시각(10/02 18:21), 영어 섞인 메일 제목.
- 실존 인물의 실명·실제 전화번호·실제 계좌번호는 쓰지 마.
- 인증번호·OTP 알림과 카카오톡 개인 대화는 만들지 마 (앱이 따로 처리함).

## 절대 규칙 (1차 결과에서 문제가 됐던 것)
- 문장 틀을 만들어 놓고 앱 이름·금액·이름만 바꿔 끼우는 방식(스크립트, 반복문, 템플릿) 금지. 한 줄 한 줄 직접 새로 써.
- 본문(text)이 같은 줄은 0개여야 해. 단어 몇 개만 바꾼 비슷한 문장도 3줄 이상 만들지 마.
- 앱과 내용이 맞아야 해. 택배 앱은 배송 얘기, 카드사는 결제·청구·카드 혜택, 메일 앱은 보낸 사람이 있는 메일, 재난문자는 재난문자 앱에서만.
  나쁜 예: 대한항공이 보낸 재난문자, 한진택배가 보낸 교수님 메일, 포켓몬 GO의 "음악 재생 중"
- 같은 앱도 알림 종류를 다르게 (예: 토스 광고 / 토스 송금 완료 / 토스 보안 경고).

## 스스로 점검
저장 전에 확인해: 라벨이 위 정의와 "헷갈리기 쉬운 경우의 정답"에 맞는지, promo yes인데 timely yes인 줄이 없는지, 앱과 내용이 맞는지.
파일은 진짜 줄바꿈으로 한 줄에 JSON 하나씩 저장해 (줄 사이에 역슬래시+n 글자를 쓰지 마).
이전 배치 파일(raw 폴더의 notif_*.jsonl)을 먼저 읽고, 거기 있는 문장과도 겹치지 않게 써.
그리고 파일을 저장한 뒤 본문 중복 개수를 세서 보고해. 중복이 1개라도 있으면 그 줄을 새 문장으로 바꿔 다시 저장해.

이번은 배치 번호 01이야. 100줄을 출력해.

## 프롬프트 2: 카톡 질문·요청

```
너는 한국어 메신저 메시지 분류 모델의 학습 데이터를 만드는 데이터 엔지니어야.
20대 한국인의 실제 카카오톡 대화처럼 보이는 합성 대화 조각을 만들고, 마지막 메시지(target)에 두 가지 라벨을 붙여.
이 데이터의 목적은 "쉬운 문장"이 아니라 "모델이 자주 틀리는 애매한 문장"을 가르치는 거야.
"몇시에 끝남", "올때 메로나좀"처럼 누가 봐도 뻔한 문장은 전체의 30%를 넘기지 마.

## 출력 형식
- JSON Lines. 한 줄에 사례 하나, 다른 설명 문장은 절대 쓰지 마. 진짜 줄바꿈으로 한 줄에 JSON 하나씩.
- 필드:
  {"room": "1:1"|"group", "context": [{"who": 이름 또는 "나", "text": 메시지}, ...],
   "target": {"who": 이름, "text": 판단할 마지막 메시지},
   "question": "yes"|"no", "request": "yes"|"no", "type": 아래 유형 중 하나, "why": 이유 한 줄}
- "나"는 이 폰의 주인이고, 대화 속에서는 "도윤"이라고 불려(예: "도윤아", "@도윤"). target은 항상 다른 사람이 보낸 메시지.
- ⚠️ target.who가 "나"인 줄은 1줄도 있으면 안 돼. 이 데이터는 "남이 나에게 보낸 메시지"를 판단하는 용도야. 내가 한 말(반어·감탄·지시 포함)은 context에만 넣어.
- context는 target 바로 앞 메시지 1~5개. 60줄 이상은 context를 3개 이상으로 해 (fragment 유형만이 아니라 모든 유형에서).
  context가 1개짜리는 20줄 이하.
- 카톡처럼 한 사람이 생각 하나를 여러 줄로 쪼개 보내는 장면을 많이 넣어. target이 그런 토막의 중간이나 끝일 수 있어.

## 라벨 1: question (나에게 진짜로 답을 원하는 질문인가)
"yes" = 보낸 사람이 "나"한테서 정보나 대답을 원함. 물음표가 없어도 됨.
"no" = 반어·감탄·혼잣말, 대답이 필요 없는 말, 문장 토막, 단톡에서 내가 아닌 다른 사람에게 묻는 질문.

## 라벨 2: request (나에게 무언가 해 달라는 요청인가)
"yes" = 보낸 사람이 "나"에게 행동을 원함. "~해줘", "~좀", "~해줄 수 있음?", "~하자", 돌려 말한 부탁 포함.
"no" = 제3자 얘기 속 명령, 감탄·농담 속 명령, 이야기 중간 토막, 단톡에서 내가 아닌 사람에게 한 요청.

## 단톡에서 누구에게 하는 말인지 (가장 중요)
- 나("도윤")를 부르거나, 내 메시지에 바로 답하며 묻거나, "다들/얘들아/누구~/~할 사람?"처럼 모두에게 하면 → 나에게 하는 말(yes 가능)
- 다른 사람의 메시지에 이어서 그 사람에게 묻거나 부탁하면 → no
  예) 성민: "주말에 풋살하실 분" → 재석: "몇시에 하는데요" (재석이 성민에게 묻는 것 → question no)
  예) 보람: "나 알바 짤림" → 태현: "사장님이 뭐라면서 짜름?" (보람에게 묻는 것 → no)
  예) 나: "나 3번 모르겠음" → 유나: "도윤아 그거 지연이한테 물어봐" (나에게 하는 요청 → request yes)
  예) 선우: "나 오늘 늦어" → 나: "ㅇㅋ" → 유진: "얼마나" (유진이 선우에게 묻는 것 → no)
  예) 태민: "오늘 비온다매 우산 챙기셈" → 동기: "비 엄청 오냐?" (태민에게 묻는 것 → no)
- 이 규칙은 plain 유형을 포함한 모든 단톡 사례에 똑같이 적용해.
- 문장 토막이라 뜻이 애매해지는 사례("점장님한테" / "전화 걸어봤냐?"처럼 이야기인지 질문인지 모호한 것)는 만들지 마.

## 유형(type)과 배치당 최소 개수 (100줄 기준)
- fragment (12줄 이상): 여러 줄로 쪼갠 이야기의 중간·끝 토막. 명령형·의문형처럼 보여도 no.
  예) 친구: "아 진짜 어이없는게" / "휴가 쓰려고" / target "서류 다 챙겨서 내고" → no/no
  예) target "근데 수비수는" (다음 줄에 말이 이어질 앞부분) → no/no
  주의: 쪼갠 줄을 이어 붙였을 때 나에게 하는 부탁·질문이 되면 토막이어도 yes야.
  예) 엄마: "주말에 집에 올때" / "아빠랑 같이 밥먹게" / target "일찍 들어오라고" → request yes
  예) 과대: "내일 엠티 출발 9시니까" / target "다들 늦지 말라고" → request yes (모두에게)
  fragment 유형은 이어 붙여도 부탁·질문이 아닌 "이야기"로만 만들어.
- self_talk (10줄 이상): 혼잣말·고민 독백. 의문형이어도 대답을 원하지 않음.
  예) "넷플 요금제 올릴까", "아 뭐 먹지", "이걸 사 말아" → no/no
  단, "너라면 살 거임?"처럼 나에게 의견을 물으면 → question yes
  주의: 1:1 대화에서 나와 함께 정할 일(신혼여행 렌트카, 같이 키우는 고양이 모래, 내 이사 날 몇 시에 갈지)을 "~할까", "~나으려나"로 말하면
  사실상 나에게 묻는 것이라 혼잣말이 아니야. self_talk는 그 사람 혼자의 일(자기 옷, 자기 점심, 자기 운동)에 대한 독백으로만 만들어.
- rhetorical (10줄 이상): 물음표가 있는 반어·감탄·비꼼. 예) "이게 말이 됨?ㅋㅋ", "누가 그걸 믿냐?", "제정신임?" → no
- exclaim_command (8줄 이상): 감탄·농담·제3자 얘기 속 명령형. 예) "그 선수 은퇴하면 무조건 감독 시켜라", "그 감독 당장 경질해라" → request no
- casual_question (12줄 이상): 물음표 없거나 줄임말인 진짜 질문. 예) "로그인 안해도 되는거임", "친선전?", "낼 몇시에옴", "저번에 만들었던거?", "너 그거 봄" → question yes
- indirect_request (8줄 이상): 돌려 말한 부탁. 예) "나 지금 손이 없는데..."(대신 해 달라), "배터리 3퍼인데 충전기 있는 사람" → request yes
- group_other (10줄 이상): 단톡에서 다른 사람에게 한 질문·요청 → no/no
- group_me (8줄 이상): 단톡에서 나("도윤")나 모두에게 한 질문·요청 → yes
- plain (나머지, 30줄 이하): 평범한 질문·요청·잡담

## 문체
- ㅋㅋ, ㅠㅠ, ㄱㄱ, ㅇㅇ, ㄹㅇ, ~임?, ~거임?, ~ㄱ?, ~함, 오타, 띄어쓰기 없음, 줄임말, 가벼운 비속어(과하지 않게).
- 관계: 친구, 가족, 동아리, 팀플, 알바, 군대 동기, 연인, 선후배. 주제도 다양하게.
- 실존 인물 실명 금지(유명인 언급은 가능).

## 절대 규칙
- 문장 틀을 만들어 놓고 이름·단어만 바꿔 끼우는 방식(스크립트, 반복문, 템플릿) 금지. 대화 하나하나 직접 새로 써.
- target 문장이 같은 줄은 0개. 비슷한 문장도 3줄 이상 만들지 마.
- target의 who는 절대 "나"가 아니야. 내가 보낸 말은 context에만 넣어.
- 이전 배치 파일(chat_*.jsonl)은 읽지 마. 읽으면 그 구조를 따라 쓰게 돼. 중복 검사는 따로 해.
- 유형 순서를 섞어서 써 (fragment 12개를 몰아 쓰지 말고 유형이 뒤섞이게).
- 이번 배치의 주제·인물은 요청 메시지에 적힌 "이번 배치 주제"에서만 골라. 그 주제에서만 나올 법한 상황으로 써.

## 스스로 점검
저장 전에 확인해: target만 보지 말고 context까지 보고 라벨을 붙였는지, 단톡에서 누구에게 하는 말인지, 유형별 최소 개수를 채웠는지.
저장 후 유형별 개수, target 중복 개수, target.who가 "나"인 줄 개수를 보고해. "나"인 줄이 1개라도 있으면 다른 사람이 말하는 새 대화로 바꿔 다시 저장해.

이번은 배치 번호 02야. 100줄을 출력해.

  대비용으로, 나에게 같이 하자는 "~하자"("이따 결승 같이 보자")는 yes로 5줄 섞어.

## 프롬프트 4: 1:1 독백 줄줄이 (2026-10-03, 보강 후 실제 카톡 오탐 증가 대응)
