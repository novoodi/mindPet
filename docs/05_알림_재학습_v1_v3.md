- 원인: 보강 카톡 100줄이 짧은 말을 대부분 yes로 가르쳤다(short_order 15줄 전부 요청, short_followup 20줄 중 15줄 질문). 실제 카톡의 "한 사람이 여러 줄로 늘어놓는 말" 속 짧은 줄을 질문·요청으로 찍게 됐다.
  (실제 메시지 예시는 공개본에서 뺐다. 짧은 독백 줄의 yes 확률이 0.07→0.91, 0.58→0.99처럼 뛰었다.)
- 합성 dev에는 이런 "1:1 독백 줄줄이" 장면이 거의 없어서 dev가 실제를 대표하지 못한다. → 독백 속 짧은 줄(대부분 no)을 채우는 데이터를 추가한다 (프롬프트 4).

### 남은 문제
- 실제 카톡 47%는 앞 대화가 없는 줄인데 합성 카톡은 5%뿐이다(프롬프트가 앞 대화를 최소 1줄 요구). 오탐은 앞 대화가 있는 줄에서 더 많아(10 vs 4) 주원인은 아니지만, 분포를 맞추면 좋다 → 앞 대화를 지운 사본을 학습에 섞는 실험(새 데이터 생성 불필요).
- 0.9 이상으로 강하게 찍는 오탐이 남아 있다: 학교 단톡 공지(다른 사람을 부르는 글), 혼잣말, 감탄사류 짧은 줄. (실제 메시지 원문은 공개본에서 뺐다.)
- 실제 정답 yes가 19개뿐이라 모델 간 차이 1~2개는 우연일 수 있다. 실제 폰 데이터를 더 모으면(폰 연결 후 DB 재추출) 평가가 단단해진다.
