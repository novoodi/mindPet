# Kev 한국어 5,000문장 확대 학습 비교 결과

## 1. 개요 및 학습 설정
- **작업 목표**: 데이터 양에 따른 한국어 지시 이행 능력의 변화를 확인하기 위해 기존 1,200문장에서 5,000문장으로 학습 데이터를 확대하고, 기존 모델 및 베이스라인과 성능을 비교 평가했습니다.
- **기반 모델**: 원본 `Kev-0.8B` 어댑터와 결정 헤드에서 새로 시작 (기존 1.2k 학습 체크포인트에서 이어서 학습하지 않음)
- **학습 데이터**: 5,000문장 (기존 1,200문장 모두 포함 + `train` 분할에서 3,800문장 추가)
  - 원본 라벨 균형을 최대한 유지 (Label 5 부족분은 다른 라벨로 보충)
- **평가 세트 (두 가지 분리)**
  1. 기존 평가 세트 (360문장)
  2. 새로운 평가 세트 (488문장, 원본 `test` 분할 내 미사용 문장만 확보)
- **학습 스펙**: 3 epochs, lr=2e-5, 배치 1, 누적 8. 
  - (총 15,000 문장 처리, 1,875 Optimizer steps)
  - 학습 시간: 약 37분 45초 (2264.574406862259초)
  - 최대 GPU 할당 메모리: 약 4.94GB (4940791296바이트, 4.60GiB)
  - 검증 세트(dev, 180문장)를 통해 `Epoch 2` 체크포인트를 Best 모델로 선정했습니다. 검증 세트에서 두 판단 모두 맞힌 개수는 Epoch 1에서 168개, Epoch 2에서 170개, Epoch 3에서 169개였습니다. 이를 근거로 가장 높은 정답률을 보인 Epoch 2를 선택했습니다.

## 2. 평가 결과 비교 (두 평가 세트 종합)

항상 No로 대답할 경우의 **개별 판단 단순 기준 정확도(Majority Baseline)**: 
- 기존 360 평가셋: 83.3%
- 신규 488 평가셋: 79.5%
*(위 수치는 각 항목별 개별 판단 정확도이며, 두 판단 동시 정답률과 직접 비교해서는 안 됩니다.)*

### 2.1. 기존 360문장 평가 세트 결과
| 지표 | 원본 Kev | 1,200문장 학습 | 5,000문장 학습 (신규) |
|---|---|---|---|
| **두 판단 모두 정답률** | 69.1% | 88.0% | **91.1%** |
| 정보 질문 F1 Score | 0.123 | 0.770 | **0.867** |
| 행동 요청 F1 Score | 0.337 | 0.820 | **0.837** |

### 2.2. 새로운 488문장 평가 세트 결과

새 평가 488문장에 대한 상세 평가는 다음과 같습니다.

| 항목 | 1,200문장 모델 | 5,000문장 모델 |
|---|---|---|
| **두 판단 모두 정답** | 441 (90.37%) | 446 (91.39%) |
| **정보 질문 (TP / FN / FP / TN)** | 84 / 16 / 8 / 380 | 88 / 12 / 11 / 377 |
| 정보 질문 Precision | 0.9130 | 0.8889 |
| 정보 질문 Recall | 0.8400 | 0.8800 |
| 정보 질문 F1 | 0.8750 | 0.8844 |
| 정보 질문 오탐률(FPR) | 0.0206 | 0.0284 |
| **행동 요청 (TP / FN / FP / TN)** | 88 / 12 / 13 / 375 | 87 / 13 / 9 / 379 |
| 행동 요청 Precision | 0.8713 | 0.9062 |
| 행동 요청 Recall | 0.8800 | 0.8700 |
| 행동 요청 F1 | 0.8756 | 0.8878 |
| 행동 요청 오탐률(FPR) | 0.0335 | 0.0232 |

> **분석 및 통계적 검증**: 
> 1,200문장에서 5,000문장으로 데이터를 확대했을 때, 두 판단 동시 정답률은 약 1.02%p 상승했습니다. 그러나 모든 지표가 향상된 것은 아닙니다. 행동 요청의 경우 오탐(FP)은 13개에서 9개로 줄었지만 누락(FN)은 12개에서 13개로 늘었습니다. 반대로 정보 질문의 경우 누락(FN)은 16개에서 12개로 줄었지만 오탐(FP)은 8개에서 11개로 늘었습니다.
> 
> 두 모델의 예측을 문장 ID로 정렬한 뒤, 각 문장의 두 판단을 함께 묶어 재표집(시드 42, 10,000회)하는 Paired Bootstrap을 수행한 결과, 정답률 차이의 95% 신뢰구간(percentile 구간)은 약 -0.61%p ~ +2.87%p로 나타났습니다. 이는 작은 개선 경향성을 보이나 불확실성이 존재함을 의미합니다.

### 2.3. 평가 절차의 한계
새 평가셋에 대해 Epoch 2와 Epoch 3의 예측 결과 파일이 모두 존재합니다. 파일 생성 시각과 같은 현재 남은 실행 기록만으로는 최종 평가를 확인하기 전에 체크포인트 선택이 확정되었음을 입증할 수 없어, **선택 시점의 독립성을 확인하지 못함**을 명시합니다. 또한, 새 평가셋(488문장)은 이미 결과를 확인하고 검증에 사용된 상태이므로, 향후 설정 조정 시 이를 '완전히 미사용한 최종 평가셋'으로 간주하여 재사용해서는 안 됩니다.

## 3. 세부 오류 및 변화 분석

### 3.1. 원본 3i4K 라벨 유형별 성능 변화
- 정보 질문 판단 시 기존 1.2k 모델 대비 5.0k 모델은 FN이 12개로 줄어 질문을 놓치는 비율이 개선되었으나, FP가 11개로 늘어났습니다.
- 행동 요청은 1.2k 대비 전반적인 오탐(FP)이 9개로 줄었으나, 누락(FN)은 13개로 오히려 미세하게 증가했습니다.

### 3.2. 1.2k 모델은 맞혔지만 5.0k 모델이 틀린 회귀(Regression) 사례
학습 데이터가 커지면서 일부 모호한 문장에 대한 판단 기준이 흔들린 회귀 사례가 존재합니다.
- *"스쿼시처럼 박진감 넘치는 운동이 어디 있나요"* (정답: No)
  - 1.2k: No / **5.0k: Yes (오탐)**
  - (분석: 수사적 의문문임에도 질문으로 오탐)
- *"모레까지 제출할 레포트 있는지 일정 살펴봐줘"* (정답: Yes)
  - 1.2k: Yes / **5.0k: No (누락)**
  - (분석: 명시적 요청임에도 놓침)
- *"저쪽으로 앉으시겠어요"* (정답: No)
  - 1.2k: No / **5.0k: Yes (오탐)**
  - (분석: 질문형 권유로, 앱 기준에서는 행동 요청이 맞을 수 있으나 3i4k 정답은 No인 데이터 한계 사례)

## 4. 최종 결론 (질문에 대한 답변)

**1. 1,200개에서 5,000개로 늘렸을 때 무엇이 개선됐는가?**
- 전반적인 두 판단 동시 정답률이 약 1.02%p 상승하는 작은 개선 경향을 보였습니다(95% CI: -0.61%p ~ +2.87%p). 

**2. 행동 요청을 덜 놓치면서 오탐도 관리되고 있는가?**
- 새 테스트셋 기준 행동 요청의 FP는 13개에서 9개로 감소하여 오탐 관리가 개선되었으나, FN은 12개에서 13개로 약간 늘었습니다. 두 모델 모두 상당히 높은 수준의 성능을 유지하고 있으나 완벽하게 누락을 통제하지는 못합니다.

**3. 어떤 유형은 여전히 실패하는가?**
- 수사적 의문문("어디 있나요?")을 실제 정보 질문으로 착각하거나, 질문형 권유("앉으시겠어요")를 3i4K 정답(No)과 다르게(Yes) 판단하는 등 화행이 복합적인 문장에서 혼동이 지속되고 있습니다.

**4. 다음 단계는 데이터 추가, 라벨 정제, 모델 설정 조정 중 무엇인가?**
- **라벨 정제(고품질 데이터 구축)**가 가장 시급합니다. 3i4K의 원본 라벨이 앱의 실제 알림 중요도 목적과 어긋나는 경우("저쪽으로 앉으시겠어요" 등)가 모델의 '오답'으로 측정되고 있기 때문에, 단정적인 양적 확대(10,000문장)보다는 앱 목적에 맞춰 검토된 **400개의 정제 데이터**를 평가/학습에 투입하는 것이 더 올바른 개선을 이끌어 낼 것입니다.
